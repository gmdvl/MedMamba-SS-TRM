# Final Comprehensive Implementation Plan

This implementation plan updates the entire G-MedMamba training pipeline to produce a robust, research-grade framework for hyperspectral image (HSI) classification using `.npy` datasets generated by `prepare_histologyhsi_bc-new.py`. The plan extends the existing architecture with comprehensive experiment tracking, reliable metric computation, spectral reconstruction capabilities, GPU performance optimization, automatic failure detection, and complete reporting suitable for research publications.

The guiding principles of this implementation are:

* Every training run must be fully reproducible.
* Every epoch must produce a recoverable checkpoint.
* Every epoch must generate a complete metrics report.
* No metric should silently become `0`, `NaN`, or `Inf`.
* Training failures should be detected automatically.
* Every termination path must generate a final experiment report.
* The model should maximize GPU utilization without sacrificing numerical stability or accuracy.
* Spectral reconstruction should become a first-class objective to enable advanced hyperspectral evaluation metrics.

# Phase 13 — Spectral Reconstruction Framework

## Objective

The current architecture is a classifier only.

To compute advanced hyperspectral reconstruction metrics, the model must generate a reconstructed spectrum that can be directly compared with the original spectral signature.

This should be implemented as a **multi-task learning framework**.

## Recommended Architecture

```text
Input HSI Cube
       │
       ▼
Spectral-Spatial Encoder
       │
       ├────────────────► Classification Head
       │
       ▼
Lightweight Spectral Decoder
       │
       ▼
Reconstructed Spectrum
```

The encoder is shared between both tasks.

This minimizes additional parameters while improving learned feature representations.

## Multi-Task Loss

Optimize

```text
Total Loss

=

Classification Loss

+

λ × Reconstruction Loss
```

where λ is configurable (for example, 0.05 by default).

The classification objective remains primary while the reconstruction branch regularizes the learned representation.

## Reconstruction Metrics

The validation pipeline must compute:

* Spectral Angle Mapper (SAM)
* Root Mean Square Error (RMSE)
* Mean Absolute Error (MAE)
* Spectral Information Divergence (SID)
* Pearson Correlation (PC)
* Peak Position Error (PPE)

These metrics must be:

* computed every validation epoch
* stored in checkpoint metadata
* written to history.csv
* included in per-epoch reports
* included in the final experiment report
* available for TensorBoard logging

The implementation should also allow selecting the best model using either:

* classification metrics only
* reconstruction metrics only
* a configurable hybrid score combining both

## GPU Pipeline Audit

Ensure GPU execution for

Minimize CPU↔GPU synchronization.

## Data Pipeline Optimization

Use

* asynchronous transfers
* configurable prefetching
* overlapped data loading

to minimize GPU idle time.

## Mixed Precision

Extend AMP support to

* training
* validation
* reconstruction branch
* inference

Maintain FP32 for numerically sensitive operations such as SID where required.

## Optimized CUDA Execution

Support optional use of

* Torch Compile
* CUDA Graphs (where compatible)
* fused AdamW
* optimized Mamba scan backend
* channels-last memory format

All optimizations should fall back safely if unavailable.

## Memory Optimization

Reduce memory consumption using

* gradient checkpointing
* efficient activation reuse
* in-place operations where safe
* elimination of unnecessary tensor copies

## Performance Monitoring

Record every epoch

* GPU utilization
* GPU memory allocated
* GPU memory reserved
* GPU peak memory
* Samples/sec

* Forward time

* Validation time

The goal is to maximize GPU throughput **without changing the mathematical behavior of the model or reducing classification/reconstruction accuracy**.

# Phase 16 — Robustness Testing and Validation

Before considering the implementation complete, validate the updated pipeline with the following scenarios:

1. **Normal convergence:** Verify all epoch checkpoints, reports, and the final report are created, and metrics evolve normally.
2. **NaN loss injection:** Confirm training stops immediately, saves the current checkpoint, records `LOSS_NAN`, and generates the final report.
3. **Validation divergence:** Simulate increasing validation loss with decreasing validation accuracy for two consecutive epochs and verify `VAL_DIVERGENCE` is triggered.
4. **Metric stall:** Force identical validation accuracy (and separately identical validation loss) for two consecutive epochs and verify the corresponding stall reason is recorded.
5. **Resume after interruption:** Interrupt training after several epochs, resume from `latest.pt`, and confirm optimizer state, scheduler, AMP scaler, counters, history, and metrics continue correctly.
6. **Metric integrity:** Verify that no reported metric contains `NaN`, `Inf`, or invalid values without immediately triggering an explicit error or stop condition.
7. **Spectral reconstruction validation:** Confirm SAM, RMSE, MAE, SID, PC, and PPE are computed correctly using the reconstructed spectra and remain consistent across resumed runs.
8. **GPU performance validation:** Measure GPU utilization, throughput, memory usage, and runtime before and after optimization to confirm improved performance without degrading classification or reconstruction accuracy.
9. **Report completeness:** Confirm `history.csv`, per-epoch JSON reports, plots, TensorBoard logs, the final JSON report, and the PDF report (when enabled) are generated for every termination path.
