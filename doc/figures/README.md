# Presentation figures

Thirty-nine SVGs across two generations.

* **fig01–fig20** were drawn for the expert deck, `doc/PRESENTATION_MedMamba_to_TRM.md`.
* **fig21–fig39** were added for the v2 deck, `doc/PRESENTATION_MedMamba_SS_TRM_v2.md`, which
  needs pictures where the expert deck used a table. They are generated by `make_v2_figs.py`.

The v2 deck uses **37 of the 39** — only `fig08` and `fig12` go unused — so almost nothing is
held out any more. The "retired" and "held out" notes in the first table describe the *expert*
deck and are kept for its sake.

All of them are vector, so they stay sharp on a projector, and each carries an explicit white
background so it is readable in GitHub's dark theme as well as light.

**Figures 19 and 20 are generated, not hand-drawn.** `make_maze_figs.py` builds an 8x8 maze, its
true solution and two dead-end detours, then renders the analogy and the refinement sequence. It
asserts that every drawn line is a walk over *adjacent* cells and that no panel overflows the
canvas — an illustration that cheated visually would undercut the point it is making. Re-run it
to restyle or reseed. Both carry *"Illustration of the idea, not model output"* on the figure
itself; keep that line if you edit them.

## Visual language

Deliberately the same palette as `paper/figures/*.svg`, so the deck and the
manuscript read as one family. Type is ~40% larger, because these are projected
rather than printed, and each figure is held to roughly seven elements.

| colour | hex | means |
|---|---|---|
| grey‑blue | `#5a6472` | inherited from MedMamba, unchanged |
| orange | `#c2703a` | ours — added or replaced |
| purple | `#6a5a92` | TRM — the recursive core |
| green | `#4e8c6a` | a good outcome / a verified result |
| red | `#b4553f` | the problem being described |

**Figure 38 exists because "stage 2, 192 channels" does not tell you what is happening.** It draws
the grid shrinking to scale, says in words what patch merging does, and explodes one block into the
channel split — the long-range half and the local half — so the room can see the mechanism rather
than read the dimensions. It replaces fig 1 on the main line.

**Figure 39 exists because TRM is defined by what it deleted**, and a deck that names HRM without
explaining it leaves the gradient slide floating.

Figures 36 and 37 carry the **integration** story — what the hierarchy is swapped for, and what
TRM's four symbols actually are in our code. Both come from Section 3.4 of the manuscript; before
they existed the deck showed the swap but never said what `x` and `y` were.

`make_v2_figs.py` asserts two things before it writes anything: that no drawn element escapes
the canvas, and that **no two text labels overlap**. The second one caught four real collisions
while these were being drawn — it is the kind of damage a bounds check cannot see.

**Held-out figures are not stale** — they are slides this version of the talk does not give.
They still build and are kept for the longer version of the deck. Figures 14 and 15 are the
results and cost figures: the 25-minute talk is architecture-only, and they are kept ready to
show during questions rather than cut. See Appendix B of the speaker script for the numbers.

**Figure 17** is the reference sheet: it follows the MedMamba paper figure's layout
(pipeline across the top, exploded detail below, legend top-right) and uses the same
palette — stage blue, merge peach, BN teal, ReLU pink, SiLU purple, SS2D green — so it
can sit beside the original without a style clash. Use it for printing and onboarding;
figures 5 and 6 are the simplified views for the talk itself.

**Figure 18 exists because an earlier GMedMamba diagram does not describe the code.**
It shows `SSI-Conv-SSM`, `3D-Conv K=3x3x3`, Spectral Pooling, Spectral Inter-channel
Attention, two Patch Embeddings and a Multi-modal Fusion block. None of those are in
`gmedmamba.py`; `gmedmamba_efficient.py:20` states outright that *"this codebase never
had a dense Conv3D spectral branch."* Every row of fig 18 was checked against the
source. Treat that older figure as a design proposal.

## Rebuilding a deck

Both builders read **PNGs**, not SVGs, from `doc/figures/_png/` — a build intermediate that is
git-ignored, so a fresh clone has to render it first:

```bash
cd doc
python3 figures/make_v2_figs.py      # regenerate fig21-fig35 (optional)
mkdir -p figures/_png
for f in figures/*.svg; do
  rsvg-convert -w 2000 "$f" -o "figures/_png/$(basename "$f" .svg).png"
done
python3 build_pptx_v2.py       # the v2 deck  - needs python-pptx + Pillow
python3 build_pptx.py          # the expert deck
```

`build_pptx_v2.py` holds its slides *and* its speaker notes in one list, and emits the PPTX, the
speaker script and the outline from it, so those three cannot drift apart. It refuses to build if
any SVG is newer than its PNG — a stale raster would embed a drawing that does not match its
source, and nothing downstream can see that.

`-w 2000` is what the current deck was built at; the layout engine only reads each PNG's
*aspect ratio*, so the width just sets projection sharpness. Override the directory with
`PPTX_PNG`, and point `PPTX_LIBS` at a vendored `python-pptx` if it isn't installed globally.

## Editing

They are plain SVG — open one and change the text, or rasterise to check a change:

```bash
rsvg-convert doc/figures/fig06_why_c_vanishes.svg -o /tmp/check.png
```

Two traps, both hit while drawing these:

* **`text-anchor` must be an inline `style`, not an attribute.** The CSS class in
  `<defs>` already sets `text-anchor:middle`, and CSS beats presentation
  attributes — so `text-anchor="start"` is silently ignored and the label clips.
* **Self‑loop arrows** need control points near the endpoints
  (`M x,y C x,y+50 x2,y+50 x2,y`). Placing them far apart pinches the curve into
  an unreadable knot.
